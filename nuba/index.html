🌙 Nuba: fast, privacy-friendly anime tracker with no email and no JavaScript

A fast, privacy-friendly anime tracker and discovery site with its own accounts (no email), instant search, and no JavaScript needed.

TypeScriptUpdated 2026-11-02
View source on GitHub

A fast, privacy-friendly tracker and discovery site. It ships configured for anime, with data from AniList, but the data source and wording are swappable: the same app can track books, games, or anything else with a catalog. Named after nubatama, an old poetic word for black.

Nuba does not host, embed or link to unofficial content. The "Where to watch" section only shows official services listed by the catalog.

Features

  • Home page with a hero carousel, shelves, a top-ranked list and a release schedule in the viewer's timezone (whatever the catalog provides)
  • Typo-tolerant search ("narto" finds Naruto) with filters for format, year, season, status, tags, studio, genre and sort, served from a local title index so it is instant and doesn't use the catalog's rate limit
  • Browsing and detail pages with outbound links and recommendations
  • Optional adult titles: a signed-in, self-declared 18+ setting, off by default
  • Settings with account tools (rename, change password, sign out other devices, export or clear your list, delete your account) and per-device display options
  • Nuba's own accounts and lists: username and password only, no email, nothing linked to a third-party account. Continue Watching row, status badges on cards, one-click progress, and a list editor on every title
  • Dark/light mode, 8 accent presets or any custom color, title language, reduce-motion
  • Works with JavaScript disabled (Tor Browser "Safest"): server-rendered pages, CSS-only menu and tabs, and plain forms for sign-in, settings and lists
  • Catalog data and images go through the server, with caching, so visitors' browsers never contact third parties

Run it

Requires Node.js 20.19+.

npm install
npm run dev        # http://localhost:5173

Production:

cp .env.example .env   # then edit it: at least ORIGIN
npm run build
npm start              # reads .env

Admins

Register an account on the site, then make it an admin on the server:

npm run admin -- <username>            # grant
npm run admin -- <username> --remove   # revoke
npm run admin -- --list                # show admins

Admins get an Admin page (account menu → Admin) with site stats, the catalog's sync status, and account tools: reset a forgotten password (there is no email, so the admin passes the new one on), grant or remove admin, delete an account. Admin rights can only be granted from the server, never through the website.

See .env.example for configuration. Accounts and lists are stored in data/nuba.db (SQLite); back up that file to back up your users.

How it fits together

Piece Where What to change to repurpose Nuba
Data source src/lib/server/catalog/ Add a folder that implements the Catalog interface in catalog/types.ts, register it in catalog/index.ts, set NUBA_CATALOG
Wording src/lib/site.ts Site name, search placeholder, unit name (episode → chapter), list status labels
Data model src/lib/types.ts Generic Item, ItemDetail, HomeFeed, used by every page
Search index src/lib/server/title-index.ts Generic. A catalog fills it with records (names, card, filter values); see catalog/anilist/crawl.ts
Accounts and lists src/lib/server/users.ts, library.ts Independent of the catalog. Each list entry stores a snapshot of its item, so lists keep working if the catalog changes or goes offline

Nothing outside src/lib/server/catalog/ knows AniList exists. Syncing lists with AniList (or another service) can be added later as a separate, optional feature.

Hosting as a Tor onion service

  1. Point a hidden service at Nuba in /etc/tor/torrc, then restart Tor:

    HiddenServiceDir /var/lib/tor/nuba/
HiddenServicePort 80 127.0.0.1:3000

  2. Your address is in /var/lib/tor/nuba/hostname. Put it in .env, with plain http (Tor already encrypts and authenticates the connection):

    ORIGIN=http://youraddress.onion
HOST=127.0.0.1
PORT=3000

    ORIGIN is required. Without it the server assumes https://, and every form (sign-in, lists, settings) is rejected as cross-site on a plain-http onion.

  3. npm run build && npm start. Keep HOST=127.0.0.1 so the server is only reachable through Tor.

Everything works in Tor Browser's "Safest" mode (JavaScript off): pages are rendered on the server, menus and tabs are CSS-only, and all actions are plain forms. Keep NUBA_IMAGE_PROXY=true so images come from your own server. Images are kept in data/images/ after the first view.

While the site is private, set NUBA_REGISTRATION=closed once your own account exists. To mirror on clearnet too, set NUBA_ONION_URL there so Tor Browser offers the onion.

Privacy and security

  • Visitors' browsers only ever talk to your server: no third-party scripts, fonts, images or analytics, enforced by a Content Security Policy.
  • No email, no IP addresses stored or logged by Nuba, no tracking cookies. Two cookies: the session (random token, only its hash stored) and display preferences.
  • Passwords are hashed with scrypt. Sign-in attempts are throttled per username and sign-ups site-wide (over Tor everyone shares one IP), with a bot trap on sign-up.
  • Profiles are private unless their owner makes them public. Avatars are picked from catalog art: there are no uploads to moderate.
  • Headers: no-referrer, no framing, nosniff, a strict permissions policy, and no-store caching for signed-in pages.
  • The image proxy only fetches https images from the catalog's own hosts and never follows redirects.

Notes

  • Passwords are hashed with scrypt; sessions are random tokens of which only a hash is stored. There is no email, so forgotten passwords cannot be reset.
  • Repeated wrong passwords for one username are slowed down per username rather than per IP, because over Tor every visitor shares an IP.
  • AniList rate-limits API clients (currently about 30 requests per minute). Nuba caches responses in memory and serves stale data while refreshing.
  • On first start Nuba downloads AniList's title list (about 22,000 anime, ~50 requests, a few minutes) into data/nuba.db, then checks for changes every 30 minutes. It pauses whenever visitors need the rate limit. Until the first pass finishes, text searches go to AniList directly.
  • Not affiliated with AniList.
